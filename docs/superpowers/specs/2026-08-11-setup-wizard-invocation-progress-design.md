# 新书设置向导 AI 任务进度设计

## 目标

修复两类前端状态失真：

1. “文风 / 世界观”生成期间长期显示 `0 / 5` 和“准备中”；
2. 自动驾驶已被手动暂停、终止或异常挂起后，项目库仍显示旧的“写作中 / 审稿中”。

保留现有 AI Invocation、审阅、轮询、提交以及世界观生成语义，不修改提示词、模型配置、自动驾驶停止语义、API 路径或既有 SSE 事件格式；项目列表只新增一个向后兼容的只读状态字段。

## 已确认事实

世界观阶段通过 `POST /api/v1/bible/novels/{id}/generate-stream?stage=worldbuilding` 建立 `bible.setup.worldbuilding` Invocation。该调用会立即发送 `approval_required`，前端随后通过 `aiInvocationStore` 轮询任务。旧的逐维 `worldbuilding_dimension` SSE 事件在此路径上不会产生，因此现有 `completedDimensions` 一直为空，直到整份结果提交。

## 方案

### 状态模型

在 `NovelSetupGuide` 中为四个可运行 AI 任务使用一个小型、纯前端的展示状态：

- 文风 / 世界观；
- 人物；
- 地图 / 地点；
- 剧情总纲。

- `creating`：请求已发出、尚未收到 Invocation 会话；
- `generating`：收到 `approval_required` 并开始观察会话；
- `validating`：任务返回候选结果，等待提交；
- `committing`：正在写入 Bible / 世界观；
- `completed`：提交成功；
- `failed`：Invocation 或流返回错误。

状态只从既有 `consumeBibleGenerateStream` 回调和 `aiInvocationStore.onSessionUpdate` 载荷导出，不发起额外请求，不改变提交时机。

### 向导展示

所有向导 AI 生成面板在 Invocation 路径中显示：

- 真实阶段名称与解释，例如“AI 正在生成完整世界观（五个维度会在完成后统一写入）”；
- 自收到任务会话起的已等待时间；
- 无障碍状态播报（`role=status` / `aria-live=polite`）；
- 明确的非伪进度说明，而不是把未产生逐维事件表示成 0/5 的失败或停滞。

统一进度条展示真实任务生命周期：创建任务、生成内容、校验结构、写入结果。它不显示虚假的百分比。世界观在完成提交时才显示完整的 `5 / 5`；人物、地点和剧情总纲在写入成功后展示已有的可编辑结果。若走旧的逐维 SSE 路径，则保留原有逐维实时更新行为。

### 流式内容展示

四个 Invocation 都已经由后端把真实模型输出块持续写入 attempt 内容，前端现有任务轮询可读取该内容。本次会在四个生成面板中显示同一份真实、持续增长的输出预览：

- 世界观：保留已能解析的字段卡片，同时在 JSON 尚未完整时显示真实原始片段；
- 人物和地点：在完整对象尚未可解析前显示真实原始片段，解析后继续保留已有角色/地点卡片；
- 剧情总纲：沿用现有实时预览，但与统一任务状态、等待时间使用同一组件；
- 预览只显示受长度上限保护的末尾片段，保留换行，避免长 JSON 导致页面持续重排；Vue 文本插值不执行模型内容。

如果服务端尚未保存任何内容，界面明确显示“等待首段输出”，收到第一段后才显示流式预览；不会用骨架动画冒充文字流。

### 错误与清理

- 出错时停止计时、保留现有错误提示与重试入口；
- 组件卸载、重新开始生成、会话完成时清理计时器与订阅；
- 同一会话不可重复启动计时或重复提交完成状态。
- 每次只为当前向导阶段绑定一个活动任务；跨步骤时旧订阅不得覆盖当前阶段的状态。

## 不做的事情

- 不拆分五维生成，不缩短提示词，不切换模型；
- 不修改 `FULL_INTERACTIVE` 策略、AI Invocation API 或 SSE 协议；
- 不把“已等待时间”伪装成模型完成百分比。

## 项目库自动驾驶状态

### 根因

自动驾驶的手动终止已经持久化 `autopilot_status=stopped` 与 `autopilot_recovery_reason=manual_terminate`，但小说列表 DTO 没有返回 recovery reason；首页卡片又只使用粗粒度 `stage`。于是 `stage=writing` 会覆盖真实的“已终止”运行态。

### 方案

- 在现有小说 DTO 中向前端公开只读的 `autopilot_recovery_reason`；这是已有持久化状态的兼容性扩展，不增加请求或改变停止接口。
- 新建一个纯前端的项目卡片状态投影函数，统一决定标签、色彩语义和圆点 key：
  - `manual_terminate` + `stopped` → “已终止”；
  - `manual_pause` + `stopped` → “已暂停”；
  - `error` → “异常挂起”；
  - 其余普通 `stopped` 状态继续显示小说生命周期（如“规划中”“审稿中”），避免把从未启动的项目误标；
  - 运行中及完成态继续显示已有的生命周期状态。
- 首页主书库和“全部书目”弹窗共用该投影，不再各自解释状态。

### 错误与兼容

旧服务端未返回 recovery reason 时前端按空值处理，保留原先生命周期标签；不会因升级顺序造成空白状态。

## 验收

1. 任何向导任务收到 `approval_required` 后，都显示“生成中”而非笼统的“准备中”。
2. 文风 / 世界观不再显示误导性的 `0 / 5`；它明确说明五维内容会统一写入。
3. 人物、地点、剧情总纲都显示创建、生成、校验、写入四个真实任务阶段和已等待时间。
4. 已等待时间递增，且会话完成、失败、重新开始、卸载时停止或重置。
5. 四个阶段都会显示真实增长的模型内容片段；未收到首段时显示等待首段，而不是虚假流式文本。
6. 已有逐维 SSE 数据仍会立即更新相应维度。
7. 已提交的世界观、人物、地点和剧情总纲仍使用原来的结果预览、缓存、确认及下一步流程。
8. 不改变现有 API 路径、SSE、停止语义或生成输出；项目列表只新增向后兼容的只读状态字段。
9. 新增可重复运行的前端行为测试，随后运行前端单测、lint 与 build。
10. 手动终止中的小说在项目库显示“已终止”，手动暂停显示“已暂停”，而普通未启动的规划 / 审稿项目仍显示其生命周期状态。
